## 审核项

### 1. 固定字段不依赖 topic

- [x] **通过**
- 发现：name/title/url plan 生成逻辑完全独立于 topic。`draft_search_plan` 中 `mode="name"` 只使用 `name` 参数，`mode="title"` 只使用 `title` 参数，`mode="url"` 只使用 `known_url` 参数。只有 `mode="topic"` 才读取 `topic_id` 并从 DB 加载 topic query_def。
- 证据：
  - `collector/discovery.py:118-158` — name/title/url 三个分支互不交叉
  - `collector/discovery.py:160-173` — topic 分支独立读取 topic_id
  - `tests/test_discovery_core.py:69-71` — name plan 测试无 topic 依赖
  - `tests/test_discovery_core.py:80-82` — title plan 测试无 topic 依赖

### 2. 主题检索不会变成无限抓取

- [x] **通过**
- 发现：
  - topic plan 有 `max_results` 限制，默认 20，硬上限 100（`collector/discovery.py:92`）
  - plan 包含 `exclude_terms` 默认值 `["reddit", "forum", "news"]`（`collector/discovery.py:113`）
  - topic plan 的 queries 来自 topic query_def 的 keywords/known_names/known_titles，不从外部输入无限扩展
- 证据：
  - `collector/discovery.py:92` — max_results clamp 到 1-100
  - `collector/discovery.py:113` — exclude_terms 默认值
  - `tests/test_discovery_core.py:95-97` — max_results 边界测试

### 3. discovery hits 不会直接污染 works

- [x] **通过**
- 发现：
  - `accept_hit_to_intake` 直接在 `intake_candidates` 表中创建记录（`collector/discovery.py:522-572`）
  - 不调用 `ingest_bridge.promote`
  - 不下载 PDF
  - 不写 works 表
  - resolution 固定为 'pending'
- 证据：
  - `collector/discovery.py:522-572` — accept_hit_to_intake 实现
  - 全局搜索无 `ingest_bridge`、`promote`、`works` 调用

### 4. accept hit 只进入 intake_candidates

- [x] **通过**
- 发现：
  - `accept_hit_to_intake` 内部直接 INSERT INTO intake_candidates（`collector/discovery.py:543-560`）
  - 设置 `resolution='pending'`、`status='pending'`、`review_status='pending'`
  - accept 后回填 hit 的 `candidate_id` 和 `review_status='accepted'`
  - 重复 accept 同一 hit 返回 `already_accepted`，不重复创建 candidate
- 证据：
  - `collector/discovery.py:522-572` — accept_hit_to_intake 实现
  - `tests/test_discovery_core.py:348-358` — 幂等性测试

### 5. agent 回填有去重和必填字段校验

- [x] **通过**
- 发现：
  - `insert_discovery_hit` 要求至少有 url 或 title（`collector/discovery.py:277`）
  - 去重基于 `run_id + dedup_key`（`collector/discovery.py:295-302`）
  - dedup_key 优先使用强标识（arxiv_id > doi > url > title，`_make_dedup_key`）
  - `batch_insert_hits` 对单条失败不中断整批
- 证据：
  - `collector/discovery.py:277` — url/title 至少一个校验
  - `collector/discovery.py:295-302` — 去重逻辑
  - `tests/test_discovery_core.py:147-155` — 去重测试
  - `tests/test_discovery_core.py:165-177` — batch 测试

## 风险项

1. **中风险：`batch_accept_hits` 不过滤 title-only low-confidence hit**
   - 计划文档（§discovery accept 轻闸门适配）要求"title-only low-confidence hit 不被批量接受"
   - 实际实现 `batch_accept_hits`（`collector/discovery.py:515-557`）不过滤，直接调用 `accept_hit_to_intake`
   - 测试 `test_batch_accept_title_only_low_confidence` 验证了当前行为：title-only low-confidence 也被接受
   - 建议：在 `batch_accept_hits` 中增加 title-only low-confidence 过滤逻辑
   - 影响：可能导致低质量候选进入 intake，但仍需人工审核

2. **低风险：`create_discovery_run` 不自动创建 manual_url hit**
   - 计划文档（§API 草案）提到"当 `executor=manual` 且 mode=`url` 时，可以同步创建一条 `manual_url` hit"
   - 实际实现不自动创建，需要单独调用 backfill 端点
   - 测试 `test_api_run_manual_url_creates_hit` 已更新为匹配实际行为
   - 影响：功能可用，只是需要多一步操作
