## 实施中的重要修正

1. MinerU 创建任务 POST 原先会因网络错误或队列响应自动重试；现在每次预留至多一次 POST。响应丢失/无效时明确保留 submission_unknown，不把“不知道是否成功”改写成“可以重新提交”。
2. 上游 task_id 在获得时立即持久化；不再只等完整解析成功后才登记。已有 task_id 的失败可按原任务查询和下载。
3. 单请求线程池无法提供全局限流，并与 resume/release 的旧全局锁不一致。本次按基础闭环要求统一保守串行；`LITLIB_PARSE_CONCURRENCY` 不再驱动旧批量入口提速。短 authority 临界区和多 worker 吞吐优化留在 #7 后续设计。
4. 备份执行与 API 进程分离，维护停止 API 后任务仍有持久状态。任何执行器异常都不自动宣称备份成功，也不盲重跑维护；主机核对实际服务和回执后才能解除 needs_attention。

## 2026-10-23 独立审核修复

归属 MIG-001 / #5 / #7 / #13，承接两名独立审核者与主 Agent 复核的四项发现。用户授权全部修复，允许提交推送，继续禁止部署。

1. 正常补录产生的 pending 不再阻断备份；只有真实执行中或未协调状态阻断。维护前失败为 failed，不锁住后续队列；一旦进入维护或阶段不明仍需人工检查。
2. 计划关联、producer 和恢复凭据同事务提交。新增 API/CLI `parse abandon`，受原有认证和 epoch 写守卫保护，在无活动解析时有审计地终止中断项；保留额度预留、未知提交证据和原文件，允许剩余项继续。旧孤立 job 必须精确指认，不猜测关联。
3. 补录核对按 Source 归属检查用途回执；Work 级空 Source 回执仍可覆盖该 Work。与解析计划的选择规则一致。
4. 恢复凭据随数据库快照保存，已知云任务冷恢复后可核对固定 PDF 并重建空输出目录，继续同一 job/task/版本；未知目录、摘要不符、无凭据和部分不可变包仍拒绝。旧已知云任务无凭据时要求先在原 slot 恢复，不发布无法续接的快照。

验证采用隔离合成库、模拟 MinerU、本地对象存储及 HTTP CLI。部署、真实额度、实际维护适配器仍另行验收；不改冻结运行材料、正式两库或科学状态。具体命令和状态语义见[客户端手册](foundation-client.md)。

## 2026-10-23 #14/#7 异步执行与原生批次

用户要求推进快速接收/短锁执行、云阶段拆分、有界容量/维护、联动故障测试四项工作，随后 #14 新增原生多文件 batch 要求。本次候选在原四项上增加批内身份与上传恢复，不用单文件线程池冒充原生 batch。

实现复用已冻结计划、预算、producer/operation 和固定资产。API 202 返回可查询任务，独立 worker 按 prepare/submit/upload/poll/download/publish 或 local 阶段领取。目录写入通过短 authority 事务检查 epoch、租约代次和 Source/最新 producer；云等待及下载不持全局写锁。旧同步模式显式保留，开启 async_parse_v1 后旧写入口要求迁移，避免暗改原响应语义。

原生批次按兼容参数聚合，批次 ID/data_id/Source/Parse版本/PDF SHA 与加密链接先提交再上传。批量查询按文件分发；成功先登记，运行继续，明确失败项可以独立重试并保留批历史。预算按文件尝试预留，POST/查询频率与在途文件数分开。临时链接用独立环境密钥加密，状态接口不返回链接。

维护 drain/snapshot 屏障与备份执行器联动。暂停/取消已提交任务继续仅跟踪云终态；未知提交可经证据核对后受控协调。Source 冲突、旧 epoch、旧租约、连续查询错误、日限、队列满与本地 busy 分列，未完成产物/未知文件保留。

独立复核发现并修复的边界包括：提交前崩溃自占容量、旧任务恢复绕过新 Source 版本、取消后上游占用不释放、持 poll 租约取消未同步业务状态、已 PUT 文件暂报 waiting-file 被误停。对应回归已加入；原 181 项测试不被当作新并发验收。新增验证只用隔离合成库、真实本地 HTTP CLI、fake provider 和本地对象存储；完整冷恢复及固定提交全量结果在本阶段交付回执记录。

新增 optional parsing 依赖复用现有锁定 pycryptodome，没有升级其版本。研究 schema/contract 不变。操作、密钥保全、默认边界、旧任务迁移和未验收范围见[手册第 8 节](foundation-client.md#8-异步解析与原生多文件批次issue-714)。本轮仍未部署、未启用实际 worker/调度、未调用真实 MinerU，也不关闭 #7/#14 的生产验收。
